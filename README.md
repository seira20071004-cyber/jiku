# jiku — 自分の宇宙

望む人生から、今日の具体的なタスクまで。Three.jsで探索する2.5Dの宇宙と、毎日の固定量・統計をつなぐ日本語アプリです。

## 使い方

初回は「ビッグバンを起こす」から宇宙名と最初の銀河を設定します。演出はスキップでき、OSの「動きを減らす」にも対応します。以前の目標がある場合はオンボーディングを省略して引き継ぎます。

- 宇宙 → 銀河 → 恒星系 → 惑星 → 衛星。新しい目標は最大5階層です。
- 各画面ではその場所の直下の天体だけを選択できます。宇宙全体に恒星系・惑星・衛星のラベルは出ません。
- 天体・名前をタップして中へ進み、パンくずや「ひとつ上へ」で戻ります。スワイプで平行移動、ピンチ・ホイール・＋−でズームできます。
- 現在地に応じた追加ボタンから天体を作成します。追加ボタンを押すと、最初に「作る銀河（恒星系・惑星・衛星）のタイプを選んでください」と表示し、「目標／タスク」を選んでから設定へ進みます。名前・この目標にした目的は必須です。上位目標は追加した場所から自動で決まり、別の階層に変更する選択肢は出しません。「タスク」の場合だけ固定量・単位・モードを入力します。見出し横の「···」から後で変更できます。
- ブラックホール名は銀河名を初期値とし、銀河の編集画面の「詳細設定」から変更できます。
- 宇宙上の管理ボタンは追加・編集・戻るだけに絞り、拡大率・目標一覧・今日のタスク・階層番号を表示しません。ピンチやホイールによる拡大縮小は引き続き使えます。
- 銀河・恒星系・惑星でも「タスク」として保存できます。子がないだけではタスクとせず、「目標」のままなら後から分解できます。「タスク」は子を作らず、分解したくなったら編集画面で「目標」へ切り替えます。下位目標のあるものは「タスク」に変更できません。切り替えてもIDと過去の記録は維持します。

モード選択は、その日初めて開いたときに1回だけ表示します。閉じた場合も同じ日は繰り返さず、記録した日は再表示しません。過去の修正は統計のカレンダーからできます。固定量はタスクごとに1つです。タスクを「休む日」に置くと全モード、「忙しい日」に置くと忙しい日と余裕がある日、「余裕がある日」に置くと余裕がある日だけに含まれます。同日の再選択で二重加算しません。手動修正はモードを変えても保持します。

下部ナビは「自分の宇宙・統計」。週間量、目標単位での集計、カレンダー、生活のモードを確認できます。設定から週次レビュー・バックアップを利用できます。タスクの種類・優先順位・状態は画面に表示せず、旧データに保存された値は互換性のため保持します。Googleプロフィール画像を右上に表示します。

## 技術と構成

通常のJavaScript ES ModulesとThree.jsを維持し、React等への移行は行っていません。esbuildでThree.jsをローカル配信用にバンドルします。

- `src/universe.js`：WebGL描画、粒子の渦巻き銀河、星雲、恒星、降着円盤、模様付き惑星・大気、Bloom、ズーム、パン・ピンチ、誕生演出。
- `dist/universe-model.js`：階層・直下の子目標・移動制限・並び替え・初回作成・既存データの移行。描画から独立しています。
- `dist/app.js`：オンボーディング、目標フォーム、探索ナビ、日々の記録・既存統計との接続。
- `dist/model.js`：既存のデータ・日付・記録・集計ロジック。
- `dist/quantity-view.js`：固定量設定・記録・週間統計。
- `dist/style.css`：暗い宇宙・フォーム・統計・モバイル・動きを減らす設定。
- `worker/`：Google OAuth・署名セッション・アクセス制御。
- `scripts/build.mjs`：WebGLバンドルと認証付きWorkerの生成。

新たな外部サービスや画像APIは使いません。星雲・惑星の模様はシェーダー、星・銀河は粒子で生成します。BloomはThree.js公式のEffectComposer/UnrealBloomPassです。画像素材のダウンロードやクラウドへのデータ移行はありません。

## データと互換性

保存キー・目標ID・親ID・タスク設定・日々のログ・統計の参照先IDは維持します。ブラウザ内の初回移行前に、元のJSONを `<保存キー>:before-universe` に保護します。バックアップ保存が失敗した場合は既存保存先への上書きを止めます。新たに `universe` メタデータ、必要な目標の `description`・`symbolName`・`order` のみを追加します。

5階層を超える古い構造も削除・結合しません。5階層目から互換一覧で参照・編集し、新たな6階層目の作成は許可しません。子を持つ途中の目標にある既存のタスク設定も保持します。既存仕様どおり、通常の自動集計の対象は末端の有効なタスクです。

Google認証とユーザー単位のブラウザ保存は維持します。サーバー保存・端末間同期はありません。ブラウザデータを消す前に設定からJSONバックアップを保存してください。[Google接続手順](docs/google-login.md)。

## 起動と検証

```sh
npm ci
npm run build
npm run dev
# http://localhost:4173
npm run check
npm test
```

公開版は生成された `dist/server/index.js` で認証を行ってからアセットを返します。`.openai/hosting.json` に既存の公開先IDを保持します。秘密情報はリポジトリ外で管理します。

## 描画負荷と制約

モバイル・少コア端末では粒子数・ピクセル比・Bloomを軽くします。一度に描画する選択対象はスマホ12個、PC24個までで、表示数が多い場合は階層を分けて整理できます。選んだ階層だけを描画し、破棄時はGPUリソースを解放します。WebGLが使えない場合は目標一覧と通常フォームへ切り替わります。

実際の宇宙の距離・縮尺・重力を再現するシミュレーターではありません。天体の外観はIDから決定し、外観に目標の優劣はありません。成長スコアや新しい時間管理機能は追加していません。

設定の「初めて開いたときの画面を見る」または `?preview=welcome#tree` から、保存データを変更しない初回体験のプレビューを開けます。途中で閉じたり最後まで入力しても、実際の宇宙と記録には反映しません。

タスク量は「1日に取り組む量」として数値＋単位をまとめて入力し、「取り組む日には10ページを記録します」のように確認できます。対象日は「毎日取り組む」「忙しい日も取り組む」「余裕がある日だけ」の3択で、対象となるモードをカード内に表示します。量はどの日も同じです。週の目標量・進捗バーは表示しません。
